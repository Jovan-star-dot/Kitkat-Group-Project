# Explicit classification criteria, version 1.0-team

The specialist instructions are authoritative. This checklist makes the decision rules easy to challenge.

| Question | Required evidence / rule | Abstention or common error |
|---|---|---|
| What is the unit and baseline? | Name mechanism, offering, process or business model; actor; date; technical and incumbent comparators separately. | Local novelty cannot establish global invention. |
| Invention? | Identifiable new technical solution relative to the stated baseline. | A useful implementation or patent label alone is insufficient. |
| Innovation? | New/significantly improved use or offering, with its proposal/prototype/availability/use stage explicit. | Positive ROI is not a definitional prerequisite; realized value still needs evidence. |
| Entrepreneurship/commercialization? | Identify who organizes resources and risk, who offers it, and evidence of market introduction/value capture. | Product availability is not proven profitability. |
| Incremental or breakthrough? | Compare change magnitude, task, outcome quality and capability against the named baseline. | Preserve competing interpretation if comparative evidence is absent; breakthrough is not synonymous with disruption. |
| Organizational significance? | Compare workflow and structural value logic; separate realized from prospective and feasibility from impact. | Low/Moderate/High/Potentially Existential are team descriptors; Undetermined is permitted. |
| Created/displaced/preserved value? | State mechanism, dependencies, net-value limits and affected actors. | No invented economics or job displacement. |
| What would change the answer? | Name contrary evidence, missing evidence, confidence and reversal condition. | A forced confident label fails the test. |

Hold the general finding stable in an organization-only contrast. Change the application finding when implementation evidence changes. Handoff boundaries and the frozen JSON contract remain binding.
